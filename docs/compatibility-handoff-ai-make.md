# Compatibility handoff for AI_MAKE process 1.7

22 October 2026. Source candidate: Fusion MCP 0.8.0 development, caller 2.0, rules 1.3.1,
32 tools. Scope/task and engineering/manufacturing schemas remain 1.0. The observed installed
validation-r2 pair used rules 1.3.0; this source update has not replaced that installation.
The preceding 0.8 source was uploaded to private workbench; it is not a public release.

AI_MAKE process 1.7 and role contracts 1.1.0 implement the K1 P01–P10 lessons within the
existing phases/reviews. Caller responsibilities include current PDS/supersession, scoped
owner reports, bounded source edits, protected interfaces, complete relevant junction/load
paths, assembly order and external owner-preset/package/toolpath evidence. The setup utility's
optional --pds checks a supplied existing path, not requirement quality or model behavior.

fusion_capabilities() stays document-free without a design. Compare full server/native runtime,
caller, rules and build identity. Its additive process_controls describes implementation,
not test receipts, and applies only when applies_to_loaded_pair is true. A same-version
mismatched bridge cannot inherit its claims. Existing signatures and the 32-tool surface stay.

State/token/job/cloud-reconcile replies default compact; fetch immutable detail pages or
section="full" when needed. Omission is not pass. Existing opt-in task.authoring uses adopted
project-qualified issue budgets; missing policy is unbounded. Trusted Python has postcondition
detection, not sandboxing/rollback. reconcile_authoring observes; restricted explicit
acknowledge_authoring preserves consumed allocation/history and never repairs or replays.
A correction needs changed strategy and remaining allocation. Missing baselines, protected
changes, lost history and unsaved cross-session identity can remain blocked.

Finite roots/ligaments, kept-tool Boolean attribution and complete remote-cut damage inference
are not general implemented validators. Actual mesh/package correspondence, effective presets,
chronological support paths and checked-output-to-printer identity remain external adapter work.
Physical execution and recording have separate authority. Checked export is not manufacturing
approval. Tests for this alignment are source/API-double and isolated offline STDIO evidence;
native identity/preflight is stubbed in that protocol harness. No new native/cloud/crash or
physical qualification is claimed. Prior native receipts qualify only their recorded build.
