# Disposable Fusion acceptance — approval required before execution

This is a prepared procedure, **not an executed test record**. Ask Mauricio to approve a named disposable cloud project, two simple native local parts and one assembly, creating/saving their cloud versions, temporary exports and checkpoints. No existing engineering model, hardware, shared project policy or GitHub branch is changed by this procedure. Record installed Fusion build, OS, account/cloud availability and both MCP versions. Retain job IDs, requests/results and actual file/version IDs.

| Case | Procedure and required observations |
| --- | --- |
| Installed protocol | Match 0.6.0 / contract 1.0 / rules 1.1.0 / 32 tools. In the existing environment run `python tests/check_mcp.py` (isolated temp journal); verify list/schema/rules/resource/jobs. |
| Native constrained helper | Create a named test component and diameter parameter, inspect scope, acquire token. Run `ctx.parametric_circle`; verify origin coincidence, native diameter expression and fully constrained status in Fusion. Change diameter, regenerate and measure, then restore and recheck. No automatic rebuild. |
| Role scope | Add a supplier-style imported part with its names retained; audit only authored part, then add supplier as dependency. It needs source-grounded interface evidence, not renamed supplier features. Required failed/missing/stale evidence must block checked export. |
| Export identity | Test nonexistent/stale/empty/mismatched targets and a parent with unselected descendants: no output artifact. Valid scoped export must disclose its scope, gaps/exclusions and revisions. Open valid STEP/STL/F3D copies and compare geometry. |
| Integrity and boundaries | Introduce a known pre-existing error outside selected scope. Show it separately, then deliberately create new damage outside the permitted set in the disposable design: job fails postconditions even if script returned. Frozen active dependency is inspected; narrow mutation is rejected. Arbitrary Python boundary violations are reported afterward, with no implied rollback. |
| Shared-instance retirement | Use two instances of one local leaf definition. Retire one through Remove; verify survivor transform, valid shared definition, timeline history and source file. Last-instance retirement excludes history from current scope. Nested/derived/jointed/rigid-group cases must stop before Remove; manually inspect projection dependencies before permitted removal. |
| Observer/writer | Acquire writer token, run independent observation, then edit using original token: still valid. Repeat with an intervening manual parameter edit: old token rejected before script code. Replay consumed token rejected. Different writer cannot replace it without release. |
| Pins and preservation | Save two parts and linked assembly. Make manual dirty assembly edits and newer cloud versions of both dependencies. Explicitly pin old refs; save exact recovery version, update first ref, repin/save, update second, repin/save. Inspect native links, joints, transforms and human edits after every step. New available pinned version must not force update; unexpected target version must block writing. |
| Uncertain cloud outcome | Only in disposable project: submit save and cancel its monitoring during upload, observe original job and actual version history. Block another mutation. Reconcile exact completed version, first without note (still blocked), then caller-confirm contents with note. Confirm no duplicate save/geometry and original cancelled/interrupted status retained. If upload finishes too quickly, mark this case untested; do not fabricate a timeout. |
| Checkpoints/experiments | Clean linked checkpoint is a JSON version/reference manifest; verify every recorded version can be found. Dirty linked checkpoint stops. Linked `try_feature` rejects before candidate callbacks/changes. Independently approved unlinked part experiment creates self-contained F3D; original stays intact. |
| Presentation/motion regression | Existing capture: verify actual PNG dimensions. Existing sampled motion: check independently expected transforms, distances/interference and restored pose; retain finite-sampling limitation. Do not demand a new continuous-proof method unless approved workflow requires one. |

Any unexpected native API behavior, new topology error, lost human edit, duplicate operation or misleading result blocks adopting that feature. Record partial state, retain journals/checkpoints and stop that test; do not erase/replay. Cleanup/deletion of the disposable cloud project is a separate user decision. Passing this procedure does not certify strength, manufacturability or physical safety.
